# Sparta track: RFQ → 50% deposit invoice agent (Instant Machinist)

Instant Machinist turns a drawing + STEP into a verified CNC program in minutes. The next manual step in a job shop is
office work: read the RFQ, find the right billing account, price the job from the rate card, key a deposit invoice,
answer the customer. This agent does that step, and Sparta Worlds tests it in a local Stripe + ticket-desk world.

- **Agent (v2, final):** `agent/quote-agent.mjs`. Claude (`claude-opus-5-5`) decides: which ticket, which customer
  (strictly by requester email/domain), which catalog prices, or ask for clarification. Code does the money math and
  every write, with job-derived idempotency keys.
- **Agent (v1, kept for the before/after):** `agent/v1/quote-agent.mjs`. Claude does everything through raw tools.
- **World:** `projects/shop-quote/` (Digital Shop template, our own `seed.json`, `missions.json`, `checks.json`),
  generated by `tools/build_project.py` from a part-agnostic job card (`tools/job_card.py` → `jobs/ftc-10.json`).

## The world (seed)
Customers: **Kestrel Dynamics, Inc.** (`cus_kestrel`, the RFQ customer, with an older KD-7 draft invoice that must stay
untouched), decoy **Kestrel Dynamic Systems LLC** (similar name, different domain), and Orbital Fabrication (open invoice).
Rate card (products/prices): 3-axis VMC $1.75/min (plus a retired $1.40 price), 5-axis $2.90/min, setup $120, CNC
programming & simulation $150/part number, 6061-T6 $0.55/in³, 7075 / 304 stock, anodize, a recurring capacity plan.
Tickets: #1 RFQ from dana.okafor@kestreldynamics.example, #2 RFQ from a protonmail address saying only "Kestrel"
(ambiguous), #3 unrelated shipping question.

## Missions and checks (agent never sees checks)
- `ftc10-deposit`: quote ticket 1 from the job card (NIST FTC-10 housing, 6061-T6, qty 10, 600 s/part **assumed**, 3 setups,
  1.625 × 3.25 × 6.5 in blank) and create the 50% deposit draft. Expected: 4 quote lines + one "Balance due on delivery (50%)"
  line, **one** draft for `cus_kestrel` totalling **$437.10** of an **$874.20** quote, ticket 1 pending + `quoted` with exactly
  one reply; KD-7 draft, decoy customer, other tickets, rate card untouched; no finalize/pay/charge/product/price/customer calls.
- `ftc10-ambiguous`: same job via ticket 2. Expected: no invoice items or invoices; one public question, `needs-info`, pending.
- Checks were validated with a scripted fixture (`tools/reference_solution.mjs`): correct writes pass, a no-op fails,
  a wrong-customer draft fails, billing on the ambiguous ticket fails.

## Test conditions
| Condition | How | Real-world case |
|---|---|---|
| normal | `starters run` | one RFQ |
| interruption | Sparta `--scenario interruption` (first connector call → HTTP 500) | API blip |
| crash | `tools/redeliver.mjs crash 2`: worker killed right after its 2nd write commits (response lost), job redelivered to a fresh process on the same world | OOM / deploy restart mid-job |
| crash-late | `tools/redeliver.mjs crash 6`: killed right after the draft is created, before the reply | same, later in the job |
| double | `tools/redeliver.mjs double`: the same job delivered twice, second starts 1.5 s later while the first runs | help-desk trigger / queue fires twice |

`crash` and `double` are agent-agnostic harnesses we wrote (no agent code changes); same world, missions and checks as normal.

## Reproduce (Linux/macOS, from this directory)
```sh
# 1. Node 24 (box has 22): portable runtime in gitignored .node/
mkdir -p .node && curl -sL https://nodejs.org/dist/latest-v24.x/node-v24.21.0-linux-x64.tar.xz | tar xJ -C .node --strip-components=1
export PATH="$PWD/.node/bin:$PATH"            # node -v -> v24.21.0
# 2. Sparta Worlds (pinned)
npm install --save-exact sparta_worlds@0.9.0-beta.3
# 3. (Optional) regenerate the project inputs from the job card
python3 tools/job_card.py ../../instant-machinist/parts/ftc-10/features.json --qty 10 --setups 3 --assume-cycle-s 600 > jobs/ftc-10.json
python3 tools/build_project.py jobs/ftc-10.json
# 4. Check-suite sanity (no model): correct fixture passes, no-op fails
(cd projects/shop-quote && npx --no-install worlds starters run --project . --mission ftc10-deposit -- node ../../tools/reference_solution.mjs deposit)
(cd projects/shop-quote && npx --no-install worlds starters run --project . --mission ftc10-deposit -- node ../../tools/reference_solution.mjs noop)
# 5. Model runs (Anthropic, claude-opus-5-5; generated limits 12 steps / 1024 tokens per turn / 120 s)
#    tools/run.sh <v1|v2> <mission> <normal|interruption|crash|crash-late|double> <evidence-name> [runs]
tools/run.sh v1 ftc10-deposit double  my-v1-double          # the original failure
tools/run.sh v2 ftc10-deposit double  my-v2-double-x3 3     # the fix, 3 fresh worlds
tools/run.sh v2 ftc10-deposit interruption my-v2-int 1
tools/run.sh v2 ftc10-ambiguous normal my-v2-amb 1
python3 tools/summarize.py --events                      # table + ../out/ftc-10/sparta.events.jsonl
```
Provider settings: `WORLDS_MODEL=claude-opus-5-5` (override via env), Anthropic Messages API direct over HTTPS.
`tools/run.sh` injects `ANTHROPIC_API_KEY` with `the environment exec --only ANTHROPIC_API_KEY`. Elsewhere, export
`ANTHROPIC_API_KEY` in the shell and replace the `` prefix in `tools/run.sh`.
No real Stripe/Zendesk keys are used anywhere; the agent refuses non-loopback twin URLs and non-twin keys.
`--evidence` refuses to overwrite: pick new names.

## Notes / limits
- FTC-10 has no verified cycle time from the core yet, so the job card uses an **assumed 600 s/part** (labelled in the card,
  the mission and the agent's customer reply). Regenerate the card with `--summary <core summary.json>` once one exists;
  the expected invoice ID in `tools/build_project.py` is deterministic for the seed and must be refreshed from a reference
  run if the line count changes.
- Material is priced from the shop's own rate card ($0.55/in³ 6061-T6, an assumption), not from a supplier quote.
- Digital Shop cannot edit drafts; a wrong proposal needs a world reset (this is why duplicates matter).
- `evidence/exploratory/` holds the first v1 runs (before the reply-count check and with 16 steps / 2048 tokens).
